# 日程地图：重叠任务数量徽章与竖向轮播 — 设计规格

**Date:** 2026-09-22  
**Revised:** 2026-09-23  
**Scope:** Web 与 iOS 日程地图模式：同一地点多任务时保留焦点任务卡并加数量徽章，点开后左侧竖向轮播、右侧显示选中任务卡  
**Out of scope:** 后端 / OpenAPI；缩放级「不同地点」聚合；轮播内改期 / 改状态 / 删除；地图上新建或拖拽改坐标；导航 / 路线；规划（Plans）；MCP

**Depends on:**  
[2026-09-15-web-task-location-map-design.md](./2026-09-15-web-task-location-map-design.md)  
[2026-09-18-ios-schedule-map-design.md](./2026-09-18-ios-schedule-map-design.md)

## Goal

1. 同一地点（或坐标几乎重合）的多条任务，地图上只出现 **一张焦点任务卡**，右上角圆形徽章标出该地点总数，不再互相整张遮盖。
2. 点这张卡后，左侧出现竖向轮播（名称、时间、优先级色），右侧中间区域显示当前选中的完整任务卡。
3. 再点右侧那张完整卡，走现有任务详情（Web 抽屉，iOS 编辑 sheet）。
4. 单任务地点的标记与点按路径不变；卡片内不再出现「等 N 项」。

---

## Decisions

| Topic | Choice |
|-------|--------|
| 分组 | 坐标 6 位小数相同，或与箱内每一条的距离都 ≤ **30 米** |
| 箱子位置 | 组内出现次数最多的 6 位坐标；并列取先出现的那条 |
| 关闭态文案 | 焦点任务卡（标题 / 时间 / 状态 / 优先级色）+ 右上角数量徽章；**不**写「等 N 项」 |
| 打开态 | 左侧竖向轮播 + 右侧选中完整卡，锚在原钉点；地图不平移、不缩放 |
| 浏览 | 竖向拖动手跟手转轮播；松手按速度滑一段后吸附最近一张 |
| 循环 | **不循环**；首尾回弹 |
| 同时打开 | 同一时刻只开一个箱子 |
| 点牌 | 点两侧露出的牌 → 转到正中；点正中牌 → 打开该任务，轮播保持展开 |
| 收起 | 点地图空白、再点箱子、向下甩回、Esc |
| 缩放聚合 | **不做**不同地点的 zoom cluster |
| 后端 | **不改** `GET /views/schedule/map` |

### Approaches considered

| Approach | Pros | Cons | Verdict |
|----------|------|------|---------|
| **A. 焦点任务卡 + 数量徽章 + 左侧竖向轮播（推荐）** | 关闭态仍是真实任务；一眼看出「这里有多条」；浏览不离开地图 | 实现量比列表大；靠近左边缘时轮播要翻到右侧 | **采用** |
| B. 继续叠卡，标题写「等 N 项」，点开 popup / action sheet | 已有代码 | 叠卡仍会整张遮住；关闭态看起来仍是一条任务 | 拒绝 |
| C. 地点箱子 + 扑克扇形 | 一眼是「一叠」 | 关闭态丢掉具体任务；和现有任务卡不连续 | 拒绝 |
| D. 缩放到最大仍重合才弹列表，否则只做 MapLibre cluster | 和早期 Web 规格接近 | 同地址搜索出来的坐标差几米时永远展不开；iOS MapKit 没有同套 cluster | 拒绝 |

## 1. 现状问题

Web（`scheduleMapPins.ts`）和 iOS（`groupScheduleMapItemsByCoordinate`）已经按 6 位小数合成一组，标记标题是「第一条标题 等 N 项」，时间和状态仍是第一条。

缺口：

1. **关闭态仍是一张任务卡**，其余任务等于没出现。
2. **坐标差几米**（同一栋楼、同一次地址搜索的抖动）不会合成，多张大卡片叠在一起，后画的完全挡住前面。
3. 打开态：Web 是地图气泡列表，iOS 是系统 `confirmationDialog`，两端不一致，也看不出「从箱子里抽出一叠牌」。

## 2. 怎样算同一个箱子

对当前筛选结果里的 `items` 在客户端分组。不改 API。

### 2.1 距离

Haversine，地球半径 **6 371 000 m**。输入是任务自带的 WGS-84 `location_lat` / `location_lng`。不要用转换后的 GCJ-02 去算距离（iOS 钉点显示仍按现有 `ChinaCoordinate` 转，但分组用原始 WGS-84）。

### 2.2 算法（原点聚类，避免沿街串成一条）

分两步，都按接口返回顺序：

1. 先用现有 `groupScheduleMapItemsByCoordinate` 按 6 位小数 key（`lat,lng` 各 `toFixed(6)` / `%.6f`）分桶。同一 key 的任务**必须**在同一箱子，后面不再拆开。
2. 再按桶扫描合并：桶的代表点 = 该桶第一条任务的坐标。并入已有箱子当且仅当代表点到该箱 **每一条** 已有任务的距离都 ≤ 30 米（完全连接，避免沿街传递）。多个箱子都满足时，取到箱子原点最近的那个。都不满足则新开箱子。原点 = 该箱第一个桶的代表点，之后不改。

30.0 米算同一箱子；大于 30 米算两个箱子。单测用固定点对锁住这条边界。

沿街两家店相距 40 米：两个箱子。同一栋楼两次搜索差 8 米：一个箱子。A–B 25 米、B–C 25 米、A–C 50 米：无论接口顺序如何，A 与 C 都不会进同一箱（二者超过 30 米）。

### 2.3 箱子锚点与名称

| 字段 | 规则 |
|------|------|
| `id` | 原点坐标的 6 位 key。只用于 React / SwiftUI 稳定身份，不展示 |
| `coordinate` | 组内 6 位 key 出现次数最多的坐标；并列取先出现的 |
| `placeTitle` | 组内非空 `location` trim 后出现次数最多的字符串；并列取先出现的。全部为空则用 i18n「这个地点」 |
| `items` | 见 2.4 排序 |
| `count` | `items.length` |

`count == 1` 画现有单任务卡，点一下直接打开该任务。  
`count >= 2` 画焦点任务卡 + 右上角数量徽章。

### 2.4 箱内排序

稳定排序：

1. 有 `start_at` 的在前，按 `start_at` 升序。
2. 无 `start_at` 的在后，保持接口相对顺序。
3. `start_at` 相同：按 `title` locale 升序，再按 `id`。

打开箱子时，正中放 **焦点任务**：

1. 有 `start_at >= now` 的，取其中最早的一条。
2. 否则取排序后的第一张。

`now` 用打开瞬间的本地时钟，打开后不再因时间流逝自动换焦点。

## 3. 关闭态：焦点任务卡 + 数量徽章

```
        ┌─────────────────┐ ②
        │ 喂猫            │
        │ 09:00 - 10:00   │
        │ 进行中          │
        └─────────────────┘
                 ●
```

| 元素 | 规则 |
|------|------|
| 卡片 | 与单任务钉点卡相同：标题、时间、状态、地点（有则显示）、左侧优先级色条 |
| 展示哪一条 | 焦点任务（2.4）：即将到来最早的一条，否则排序后第一张 |
| 角标 | 卡片右上角圆形气泡，阿拉伯数字 `count`，封顶展示 `99+`。`count <= 1` 不画 |
| 卡片内文案 | **不**再写「等 N 项」 |
| 钉点 | 保留现有底部圆点，颜色跟焦点任务优先级 accent |
| 命中 | 整张卡 + 钉点都可点；点开进入轮播，不直接打开抽屉 |

读屏：`{title}，{time}，{status}，{location}，共 {count} 个任务，点按查看`。打开时原钉点隐藏（`opacity: 0` / 不画 Annotation），由 overlay 承接同一位置的选中卡和钉点。`aria-expanded` 在打开时为真。

Web 现有 `moreItems`「{title} 等{count}项」不再用于地图标记。新增 / 沿用 i18n：

| key | zh | en |
|-----|----|----|
| `pinClusterAria` | `{title}，{time}，{status}，{location}，共 {count} 个任务，点按查看` | `{title}, {time}, {status}, {location}, {count} tasks, double tap to browse` |
| `chestTasks` | `{count} 个任务` | `{count} tasks` |
| `chestPlaceFallback` | `这个地点` | `This place` |
| `fanAria` | `第 {current} 张，共 {total} 张，{title}，{time}，{status}` | `Card {current} of {total}, {title}, {time}, {status}` |

iOS 用同语义的中文硬编码（与现有日程地图一致）。

## 4. 打开态：左侧竖向轮播 + 右侧选中卡

### 4.1 几何

轮播锚在该地点的屏幕钉点。原关闭态钉点隐藏。地图相机不动。

```
   ┌────┐
   │ 简 │
   │ 卡 │     ┌─────────────────┐ ③
   ├────┤     │ 遛狗            │
   │选中│ ──► │ 11:00 - 12:00   │
   │ 64 │     │ 未开始          │
   ├────┤     └─────────────────┘
   │ 简 │              ●
   └────┘
```

| 参数 | Web | iOS |
|------|-----|-----|
| 轮播槽位 | 64×64px 圆角砖 | 64×64pt |
| 相邻槽距 | 58px | 58pt |
| 同时可见 | 正中 1 + 上下各 2 | 同左 |
| 正中 | scale 1.00，opacity 1.00 | 同左 |
| ±1 | 缩小约 0.22，透明度约 0.28 | 同左 |
| ±2 | 继续缩小，更淡 | 同左 |
| 更外侧 | 不渲染 | 同左 |
| 选中卡 / 关闭态卡 | 固定 **200×96**，折叠与展开同一尺寸 | 同左 200×96pt |

轮播砖：任务名称（最多两行）、时间、背景用该任务优先级色。已完成 / 已归档沿用现有降饱和。

右侧选中卡与关闭态钉点卡同一固定尺寸（200×96），锚在同一地理点：钉点底边落在坐标上，卡片在钉点上方 4px。数量徽章画在卡片外层，不要被卡片 `overflow` 裁切。点这张卡打开任务详情，**轮播保持展开**（仍显示刚才滑到的那张）。打开态命中要用点击坐标下的元素判断，不能用被 pointer capture 改写后的 `event.target`。

正中轮播砖 z-index 最高，越靠边越低。选中卡高于轮播。

### 4.2 展开 / 收起动画

| 阶段 | 时长 | 行为 |
|------|------|------|
| 进入 | 320ms | 轮播砖落到竖向槽位；选中卡出现在钉点上方 |
| 吸附 | 220ms | 松手后弹到最近整数 index |
| 收起 | 立刻卸 overlay | 点空白 / Esc 关闭。点选中卡打开详情，**不**收起轮播 |

缓动：展开 / 吸附 `ease-out`。

只有 2 张也走同一套轮播和手势，只是上下不对称。超过 5 张：竖列始终最多 5 张，其余从上下进出。

### 4.3 屏幕边缘

用钉点的屏幕坐标决定轮播在左还是右，**不移动钉点、不移动地图**。

| 钉点位置 | 轮播 |
|----------|------|
| 默认 | 在选中卡左侧 |
| 靠近左边缘，左侧放不下 64 + 间距 | 翻到选中卡右侧 |

实现时先算理想槽位，再做一次钳制；不要改分组坐标。

## 5. 轮盘滑动

交互面是整块 overlay（含左侧轮播砖和右侧选中卡），不是地图。拖动手势按 **竖向 dy** 换算，复用原扇形的阻力 / 吸附公式。

| 手势 | 行为 |
|------|------|
| 竖向拖 | 轮播跟手。位移换算：`deltaIndex = -dy / 58`（58px/pt = 一张）。`index` 可为小数 |
| 松手 | `index` 先加 `clamp(-vy / 900, -1.25, 1.25)`，再四舍五入到最近整数，再钳到 `[0, count-1]`，然后 **220ms ease-out** 吸附 |
| 首尾 | 超出部分乘 0.35 阻力；松手弹回 0 或 `count-1`。**不循环** |
| 点 vs 拖 | 按下后位移 < 8px / 8pt 且 `|v| < 200` px/s（iOS 同数值 pt/s），视为点按；否则视为拖 |
| 点轮播砖 | 吸附到那张，**不**打开任务 |
| 点右侧选中卡 | 打开该任务的现有详情，**保持**轮播展开与当前 index |
| 点地图空白 | 收起 overlay |
| Web 键盘 | `ArrowUp` / `ArrowDown` 一次一张；`Enter` / `Space` 打开选中卡；`Escape` 收起 |
| 滚轮 | 忽略，避免和地图缩放抢手势 |

打开轮播期间：

- **锁住地图**平移和缩放。Web：打开期间 `dragPan.disable()`、`scrollZoom.disable()`、`touchZoomRotate.disable()`，收起后恢复。iOS：打开期间 `Map` 设 `interactionModes: []`，收起后恢复默认。overlay 以外的点击仍算「点空白」并收起。
- 筛选变化或 `items` 刷新：若当前打开组的任务 id 集合与刷新前不同，立刻收起。id 集合相同则保持 index（若原 index 越界则钳到末张）。
- 打开任务详情后 overlay **保持展开**，仍停在刚才滑到的 index。保存后若任务 id 集合不变则继续开着；集合变了才收起。删除当前任务后按现有身份规则收起。

读屏：每转到一张通报「第 {n} 张，共 {count} 张，{title}，{time}，{status}」。提示「上下滑动切换，点按右侧卡片打开」。原钉点按钮在打开时 `aria-expanded=true` 并隐藏。

## 6. 两端形态

交互状态机相同，容器跟现有地图走。

```
关闭 ──点带徽章的任务卡──► 已打开（可竖滑轮播、可点砖）
                                │
                                ├─点右侧选中卡──► 打开任务详情（轮播保持展开）
                                └─点空白 / Esc──► 关闭
```

### Web

- 继续 MapLibre + 自定义 HTML Marker。单任务与多任务都用 `createScheduleMapPinElement`；多任务卡带右上角数量徽章。
- 打开后隐藏该 Marker，在画布上用绝对定位 overlay，用 `map.project` 跟钉点坐标，窗口 resize / 若相机被外部改动时重算。
- `onItemClick` 仍由页面打开 `TaskDrawerWithComments`。
- 用户可见文案走 `scheduleMap.*` 的 zh / en key，改完跑 `npm run test:i18n`。

### iOS

- 去掉 `confirmationDialog("选择任务")`。
- 多任务是 `Annotation` 里的焦点任务卡 + 数量徽章；打开后不画该 Annotation。
- 轮播是盖在 `Map` 上的 overlay：用 `MapReader` 把坐标转成屏幕点。手势用 `DragGesture`，速度用 translation / 时间。
- 点右侧选中卡走现有 `onTaskTap` → `TaskEditorView(mode: .edit)`。
- 文案继续中文硬编码，与现有 `ScheduleMapView` 一致。
- 动画与 Web 同套时长：展开 **320ms ease-out**（轮播砖从选中卡中线摊开），松手吸附 **220ms**，收起 **280ms**。折叠卡与展开后选中卡共用同一张 200×96 任务卡（左侧 3pt 优先级色条、右上角数量徽章）。

两端都 **不** 在轮播里改坐标、改时间、改状态。

## 7. 技术边界

纯函数与平台 UI 分开，Web / iOS 各写一份同语义实现（现有分组已经是这个模式）。

| 单元 | 路径（建议） | 职责 |
|------|----------------|------|
| 分组 / 排序 / 焦点 | Web `codes/web/src/lib/scheduleMapClusters.ts`；iOS `ScheduleMapFilters.swift` 旁或新 `ScheduleMapClusters.swift` | 30 米聚类、锚点、placeTitle、排序、初始焦点 index |
| 轮盘数学 | 同目录 `scheduleMapFan.ts` / `ScheduleMapFan.swift` | 竖向 `deltaIndex`、阻力、松手吸附、可见窗口 ±2、轮播左右侧 |
| 单测 | `scheduleMapClusters.test.ts`、`scheduleMapFan.test.ts`；`ScheduleMapFiltersTests` 或新 `ScheduleMapClustersTests` | 锁住 30 米边界、串街不合并、排序、吸附、徽章、轮播槽位 |
| 关闭态钉点 | Web `createScheduleMapPinElement` 徽章；iOS `ScheduleMapPinLabel` 徽章 | 焦点任务卡 + count |
| 轮播 overlay | Web `ScheduleMapFanOverlay.tsx`（由 `ScheduleMapCanvas` 挂）；iOS `ScheduleMapFanOverlay` | 竖向轮播、选中卡、手势 |
| 画布接线 | `ScheduleMapCanvas.tsx`、`ScheduleMapView.swift` | 单卡 vs 徽章卡、隐藏打开钉点、锁地图、打开详情 |

`groupScheduleMapItemsByCoordinate` 只做 6 位相同分组，供单测和 `clusterScheduleMapItems` 内部第一步使用。对外画点只走 `clusterScheduleMapItems`（6 位分组 + 30 米原点合并）。

不改：

- `GET /views/schedule/map`
- 日历 / 四象限 / 泳道
- 任务抽屉 / iOS TaskEditor 内部
- 健康页路线图

## 8. 错误与空态

| 情况 | 行为 |
|------|------|
| 筛选后某组只剩 1 条 | 变成普通单任务卡；若该组正打开则收起 |
| 筛选后组被清空 | 标记消失；若正打开则收起 |
| 地图加载失败 | 沿用现有错误条 / toast，不进入轮播 |
| 打开详情失败 | overlay 保持展开；走现有抽屉 / sheet 错误 |

## 9. 测试

### Web

- `clusterScheduleMapItems`：分坐标保持两组；同 6 位合成一组；29.9m 合一、30.1m 分开；A–B–C 链式 25m 不把 A 与 C 收进一组。
- 关闭态不再出现「{title} 等{count}项」；`countDisplay` 为徽章数字，单条为空，超过 99 为 `99+`。
- 锚点取众数坐标；`placeTitle` 取众数地点名。
- 排序：有时间升序，未排期在后。
- 焦点：未来最近一条；全是过去则第一张。
- `scheduleMapReelSlot` / `scheduleMapReelSide`：竖向槽位，靠近左边缘翻到右侧。
- i18n：`npm run test:i18n`。

### iOS

- 与 Web 同语义的聚类 / 排序 / 焦点 / 吸附单测（`TimiaTests`）。
- 回归：单任务点 Annotation 仍直接 `onTaskTap`；不再出现「选择任务」系统菜单。

### 手动

- 同一搜索地址两条任务 → 一张焦点卡，右上角徽章 2。
- 点开 → 左侧竖向轮播、右侧选中卡；上下拖能换任务；点右侧卡进详情。
- 点空白收起；打开时地图拖不动。
- 钉点靠近左边缘时轮播翻到右侧。
- 筛掉部分状态后徽章数量或单卡形态更新正确。

## Success criteria

- 同一地点多任务时，地图上只能点到一张带数量徽章的焦点任务卡，看不到被整张盖住的第二张任务卡，卡片内没有「等 N 项」。
- 点这张卡能看到该地点全部任务：左侧竖向轮播，右侧是当前选中的完整卡。
- 点右侧选中卡打开的是那一张，不是组内的第一条。
- 单任务地点行为与现在一致。
- 无后端协议变更。
